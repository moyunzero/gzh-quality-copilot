# PRD: GZH Quality Copilot（公众号质量 Copilot）

*Working title — 正式中文品牌名仍为 `[ASSUMPTION: 暂用「公众号质量 Copilot」/ GZH Quality Copilot]`。*

## 0. Document Purpose

本 PRD 服务开源 **launch**：给维护者、下游 Spec/Ticket/实现 Agent 一份可切能力的需求契约。词汇以 §3 Glossary 为准；能力以全局编号 FR 为准。它建立在已定稿的 Product Brief 与 PRFAQ（诚实框架 A）之上，不重复新闻稿文案；机制细节、五端路径表、竞品 URL 见同目录 `addendum.md`。

## 1. Vision

微信公众号作者普遍能发文，却很难把后台数据变成下一篇的改进：工具要么只导出表格，要么只吐标题公式，要么一句话写完进草稿箱——中间缺少「用自己的证据说清相对好坏 → 结构对照 → 可验证实验 → 再量」的闭环。

**GZH Quality Copilot** 是开源的质量复盘副驾驶：以标准 Agent Skills 跑在作者已在用的 AI 工具里，读取本号导出或粘贴的历史数据与可选草稿，产出固定结构的复盘、结构对照与标题/内容实验清单。运行时大模型由用户本地 Agent 提供；开源交付的是流程、诊断框架、`references/` 结构规律摘要、提示词与（可选）本号导出扩展。

**不做**破解推流、保证推荐或保证爆款。价值在于：少盲发、多留下可对照的质量决策。

## 2. Target User

### 2.1 Jobs To Be Done

- **功能：** 用本号历史表现做相对复盘；对照赛道结构规律；带着 1–3 个单变量实验写下一篇。  
- **情感：** 在几乎没人看时仍感到「我不是在瞎猜」，信心来自证据而非玄学。  
- **情境：** 已在 Cursor / Claude Code / Codex / WorkBuddy / OpenClaw 之一工作；愿意导出或粘贴后台数据。  
- **Dogfood：** 短篇小说赛道作者；维护者历史语料作第一案例（「60+ 篇」仅为案例量级，**非**入场门槛）。

### 2.2 Non-Users (v1)

- 要「装上就涨粉 / 保证上推荐」的人。  
- 完全不使用任何支持的 Agent 的人（轻量 Web 属 Later）。  
- 核心需求是系统扒竞品真实阅读量的人（应使用商业监测类工具）。

### 2.3 Key User Journeys

**UJ-1. 林修用自己的历史数据跑完第一次复盘。**  
- **Persona + context：** 林修，短篇小说公众号作者，阅读长期个位数，已在用 Cursor，有几十篇已发表。  
- **Entry state：** 已登录公众号后台或手头有导出表；Cursor 已装好。  
- **Path：** 按 README 复制一条安装命令 → 看权限清单 → 扩展导出或粘贴 CSV → 触发复盘 Skill → 得到结论/因子（按篇数降级）→ 可选读 `references/` 或粘贴对标 → 拿走 ≥3 标题候选 + 1–3 实验。  
- **Climax：** 他能指着报告说「下一篇只改开头钩子这一个变量」。  
- **Resolution：** 实验写入自己的笔记；发文后准备再导入新数据。  
- **Edge：** 扩展因改版失败 → 改粘贴导入，核心路径仍绿。

**UJ-2. 阿宁篇数很少，把工具当结构教练。**  
- **Persona + context：** 阿宁，开号两周，只发过 5 篇，阅读个位数。  
- **Path：** 安装 → 粘贴少量数据或示例 → 系统按篇数降级，不做假装的个人史分位 → 输出结构对照 + 1 个实验。  
- **Climax：** README/报告明确告诉她「样本不足，不装懂你的数据」。  
- **Resolution：** 养成发后对照习惯，而不是失望卸载。

**UJ-3. 外部作者不改代码复现「导入→报告」。**  
- **Persona + context：** 陌生作者，用 Claude Code，非短篇赛道。  
- **Path：** 从 GitHub README 安装 → 用示例 CSV 或自有粘贴 → 跑出四块输出；非短篇靠自粘贴对标。  
- **Climax：** 零改代码完成演示路径。  
- **Edge：** 不用 Agent → MVP 明确不覆盖。

## 3. Glossary

- **作者（Author）** — 使用本产品的微信公众号运营者（个人为主）。  
- **本号数据（Own-account data）** — 作者自己公众号已发表内容的表现数据（如标题、阅读、点赞、在看等），经导出或粘贴进入分析。  
- **历史篇数（Article count）** — 参与复盘的已发表文章条数；决定复盘深度，**不是**阅读量。  
- **相对复盘（Relative review）** — 仅在本号内部比较高低与因子，不要求绝对高阅读，不声称因果推流。  
- **篇数降级（Count degradation）** — 按历史篇数自动降低结论强度的产品行为（见 FR-6）。  
- **结构规律摘要（Structure summary）** — `references/` 中人工标注的公开样本结构说明；无全文；出处可查。  
- **对标粘贴（Pasted benchmark）** — 作者自行提供的公开文章正文或链接，用于结构拆解。  
- **实验（Experiment）** — 下一篇可执行、尽量单变量、发后可用新本号数据对照的改动项。  
- **依据片段（Evidence snippet）** — 报告中支撑某判断的具体引用（表行、正文段或某条结构规律摘要）。  
- **推测（Speculation）** — 无依据片段支撑的判断标注。  
- **Agent Skill** — 符合 Agent Skills 标准的技能包（含 `SKILL.md` 与可选 `references/`）。  
- **导出扩展（Export extension）** — 在作者已登录的公众号后台读取本号已发表数据并导出为本地文件的浏览器扩展。  
- **粘贴导入（Paste import）** — 不经扩展、由作者粘贴或手工提供本号数据的路径；永久一等公民。  
- **输出四块（Four-block output）** — 结论 / 因子 / 候选 / 实验。

## 4. Features

### 4.1 安装与预期对齐

**Description:** 作者在已用 Agent 中安装 Skills，并在开始前理解权限与篇数预期。Realizes UJ-1, UJ-2, UJ-3.

**Functional Requirements:**

#### FR-1: 五端安装入口

作者可按 README 中面向其 Agent 的单一安装命令完成 Skills 安装（覆盖 Cursor、Claude Code、Codex、WorkBuddy、OpenClaw）。Realizes UJ-3.

**Consequences (testable):**
- README 为每个支持端提供可复制命令（或明确「该端用通用 npx」）。  
- `[ASSUMPTION: 首跑「约数分钟」仅在五端冒烟通过后写入；否则改为「按文档操作」]`。

#### FR-2: 权限清单（非技术可读）

README 提供权限清单，说明导出扩展会做/不会做之事，作者无需读源码即可核对。Realizes UJ-1.

**Consequences (testable):**
- 清单至少覆盖：只读本号已登录后台已发表数据；导出到本地；不代持登录；不代发；不读他号；不上传至本项目服务器。  
- 清单与扩展实际行为不一致视为缺陷。  
- README 须另辟（或同节）**三层隐私说明**，与 Customer FAQ Q5 同义：① 扩展导出留本地；② Skills 开源跑在作者 Agent；③ 贴进对话的表格/正文会发给**作者选用的**模型服务商（「导出在本地」≠「贴进对话仍不出电脑」）。

#### FR-3: 新人/老人预期对齐文案

产品文档明确：「有历史篇数 → 复盘你自己；篇数很少 → 先当结构教练 + 实验本，不装懂你的数据。」Realizes UJ-2.

**Consequences (testable):**
- README How to Participate（或等价节）含上述句意。  
- 报告在篇数不足时不得输出假装精确的个人史分位结论（见 FR-6）。

### 4.2 本号数据输入

**Description:** 本号数据经扩展或粘贴进入分析；扩展失败不得阻断核心价值。Realizes UJ-1.

#### FR-4: 粘贴导入一等公民

作者可仅通过粘贴/手工提供本号数据完成相对复盘与实验输出，无需扩展。Realizes UJ-1 edge。

**Consequences (testable):**
- 无扩展环境下，使用示例 CSV 或粘贴数据可产出输出四块。  
- 文档将粘贴列为永久降级路径，而非临时凑合。

#### FR-5: 导出扩展（本号已发表）——首发必含

**决策（2026-10-20）：** 第一个公开发布 tag **必须包含当时可用的导出扩展**；不可仅用粘贴路径开源首发。粘贴导入仍为发版后的永久降级路径（扩展改版失效时）。  

在作者已登录后台时，扩展可导出本号已发表文章表现数据为本地 CSV/JSON。

**Consequences (testable):**
- 首个公开 tag 的仓库含可安装扩展，且在当前微信公众号后台版本上能成功导出至少一份本号数据（或维护者签字的当周冒烟记录）。  
- 导出字段足以支撑相对复盘（至少含标题与主要互动指标；精确列名见 addendum 输入契约草案）。  
- 扩展不实现代持登录、代发、他号抓取、上传本项目服务器。  
- 扩展日后失效时，文档与 Skills 仍支持粘贴导入（FR-4），但不因此豁免「首发无扩展」。

### 4.3 相对复盘（含篇数降级）

**Description:** 基于本号数据做相对复盘；深度由历史篇数决定。Realizes UJ-1, UJ-2.

#### FR-6: 篇数强制降级

系统按历史篇数降级结论强度：

| 历史篇数 | 行为 |
|---------|------|
| ≥30 | 允许相对排序 + Top 因子；阅读极低时因子标低置信 |
| 10–29 | 粗分「稍好/普通/较差」+ 结构对照 + 1–2 实验；不做细分位 |
| &lt;10 | 不做排序；结构规律摘要 + 对标粘贴 + 1 个结构实验 |
| 几乎无稿 | 检查清单模式；不编造个人史证据 |

**Consequences (testable):**
- 对 &lt;10 篇夹具数据运行复盘时，输出不含细粒度个人分位排序。  
- 文档与报告均不得将「阅读量个位数」表述为无权使用。

#### FR-7: 相对复盘输出

在适用降级档位下，作者获得相对复盘结论与 Top 因子（或降级后的等价物）。Realizes UJ-1.

**Consequences (testable):**
- 输出属于输出四块中的「结论」「因子」部分。  
- 不声称微信推荐算法因果。  
- **≥30 篇档：** 结论至少含 ≥3 篇相对排序或分位说明；因子 ≥2 条，每条点名比较依据（如标题形态 / 发布时间 / 互动比）。  
- **10–29 篇档：** 结论须给出粗分档结果（稍好/普通/较差）及所依据的篇目标识；因子可减为 ≥1 条。  
- **&lt;10 / 几乎无稿：** 明确声明「不做个人史排序」；不得输出细粒度相对排名表。

### 4.4 结构对照与标题实验

**Description:** 结构规律摘要 + 对标粘贴；标题/开头/实验清单。Realizes UJ-1, UJ-3.

#### FR-8: 可审计的结构规律摘要

仓库提供短篇赛道结构规律摘要：人工标注公开样本、无全文、出处可查。Realizes UJ-1.

**Consequences (testable):**
- `references/`（或文档约定路径）存在来源清单页。  
- 摘要条目不含他人文章全文。  
- 首发至少 **≥5 条**短篇结构规律摘要；每条含：结构信号说明 + 出处类型/样本说明（可核对、仍无全文）。空壳清单页视为未满足 FR-8。

#### FR-9: 对标粘贴结构拆解

作者可粘贴公开对标正文/链接，获得结构拆解；值不值得学由作者判断。Realizes UJ-3.

**Consequences (testable):**
- 无对标粘贴时，仍可仅用结构规律摘要运行（短篇）；非短篇文档说明需自备对标。  
- 默认不提供扒竞品真实阅读量能力。  
- 拆解输出至少覆盖 addendum §E 中的 **3 项**：开头钩子、标题结构、段落/节奏（或文档声明的等价三维）；并声明「价值判断由作者定」。

#### FR-10: 标题候选与实验清单

作者获得 ≥3 个标题候选、开头/结构方向，以及 1–3 个尽量单变量的实验。Realizes UJ-1.

**Consequences (testable):**
- 单次完整成功路径输出满足：输出四块齐全。  
- 实验描述可被作者事后用新本号数据对照（对照动作可由作者人工完成；系统应提示回灌）。

#### FR-11: 依据片段与推测标注

重要判断须带依据片段；否则标为推测。Realizes UJ-1；支撑 vs 裸聊差异。

**Consequences (testable):**
- 夹具报告中，至少一条因子或结论含可定位依据（表行标识或引用句）。  
- 无依据的断言不以「确定事实」口吻呈现。

#### FR-12: 固定输出四块

完整分析路径产出结论 / 因子 / 候选 / 实验 四块结构（降级档可削弱某块深度但不得改用随意闲聊结构）。 

**Consequences (testable):**
- Skill 提示词或编排规定四块标题或等价固定骨架。

### 4.5 分发与示例

#### FR-13: 示例数据与演示路径

仓库提供脱敏示例 CSV（或等价）及「导入→报告」演示说明。Realizes UJ-3.

**Consequences (testable):**
- 陌生人仅用示例数据可不改代码跑通一次输出四块（在已装 Agent 前提下）。

#### FR-14: 发现与触发

Skills 的 `description` 含中文触发词；README 作为中文主落地页指向安装与预期对齐。 

**Consequences (testable):**
- README 含安装、权限清单（含 FR-2 三层隐私）、预期对齐、诚实边界（不保证推荐）。  
- README 含合规禁令句：禁止用于破解推流/保证推荐话术；禁止未授权批量采集他号。  
- 首个公开 tag 仓库根目录含已选定的 SPDX LICENSE 文件（具体 SPDX id 发版前按最佳实践选定；**未选 LICENSE 不得打公开 tag**）。

## 5. Non-Goals (Explicit)

- 保证推荐位、保证爆款、破解或预测推流算法。  
- 代持登录、自动进草稿箱、代发。  
- 默认大规模爬取他人账号或真实阅读量。  
- 托管 SaaS、本项目侧账号体系、商业 SLA。  
- 首发即装满全赛道专家库。  
- 服务完全不使用 Agent 的作者（Later: 轻量 Web）。

## 6. MVP Scope

### 6.1 In Scope

- Agent Skills：相对复盘、结构对照、标题与实验（可用一个或多个 Skill 文件组织，能力须覆盖 FR-6–FR-12）。  
- 粘贴导入 + 示例数据。  
- **可用导出扩展（FR-5）——首发硬门闩。**  
- 短篇结构规律摘要（可审计）。  
- 中文 README：安装矩阵、权限清单、预期对齐、禁令。  
- Launch blockers：FR-2（含三层隐私）、FR-5、FR-6、FR-8（含 ≥5 条实质摘要）、FR-11、FR-14（禁令 + LICENSE 文件）发版前必须为真。

### 6.2 Out of Scope for MVP

- 自动对标 / 付费热度 API（Later）。  
- 社区赛道模板市场（Later）。  
- 轻量 Web 上传（Later）。  
- 多语言 README（v1 中文优先）。

### 6.3 发布顺序（非目标日期，是门闩）

1. Dogfood 竖切：维护者真实本号数据「结论→实验→（计划）发后对照」至少一次。  
2. 可用扩展冒烟：当前后台版本导出成功。  
3. **Skill vs 裸聊对照：** 同份 CSV，留存对照记录，可见篇数降级 / 依据片段 / 输出四块稳定性优于随意闲聊（SM-2 证据）。  
4. 可安装开源：示例路径绿 + launch blockers 绿 + LICENSE 已选并入库 → 才打第一个公开 tag / 开源海报。

## 7. Success Metrics

**Primary**

- **SM-1：** 外部作者不改代码完成「示例或自有粘贴 → 输出四块」。Validates FR-4, FR-12, FR-13.  
- **SM-2：** 同份本号数据，Skill 路径相对裸聊可演示：篇数降级、依据片段、固定四块更稳定。Validates FR-6, FR-11, FR-12.  
- **SM-3：** 维护者完成一次 dogfood 竖切并留下实验记录。Validates launch gate.

**Secondary**

- **SM-4：** README 安装路径在声明支持的端上冒烟通过；未通过的端从「数分钟」话术中移除或降级描述。Validates FR-1.  
- **SM-5：** `[ASSUMPTION: 90 天内出现有意义的 star/issue；具体数字发版前再定或保持定性]`。

**Counter-metrics（勿优化）**

- **SM-C1：** 单篇阅读量上涨 —— 噪声大且平台主导；不作为产品成功主指标。Counterbalances vanity「涨粉」叙事。  
- **SM-C2：** 扩展安装率 —— 若牺牲粘贴路径完整性则危险。Counterbalances SM 对扩展的过度依赖。
