# Product Brief: GZH Quality Copilot（仓库名 gzh-quality-copilot）

## Executive Summary

微信公众号作者普遍能「发文章」，却很难系统复盘：后台数据散落、爆款难拆解、标题/开头改了也不知道对不对。GitHub 上已有抓数插件、对标 Skill、标题公式 Skill，但几乎都是单点工具——缺一条「自有数据 → 诊断 → 可执行修改建议 → 再复盘」的闭环。

**GZH Quality Copilot** 是开源的公众号质量助手：用 Agent Skill 跑在作者已在用的 AI 工具里（Cursor / Claude Code / Codex / WorkBuddy / OpenClaw），读取作者导出或粘贴的历史数据与草稿，结合大模型做复盘、爆款拆解与标题/内容修改方向；GitHub 仓库即主落地页，附安装矩阵与演示。

不做「破解推流 / 保证爆款」。价值在于：**用证据说话的复盘 + 可验证的下一篇实验**。作者本人以短篇小说赛道、60+ 篇历史文章作为第一狗粮与案例。

## The Problem

- **数据在手里用不起**：后台有阅读/点赞/在看，导出后仍需自己做表、猜原因。
- **爆款可遇不可学**：看到别人爆了，缺结构化拆解（标题、开头、节奏、互动信号）。
- **优化靠感觉**：标题 Skill 很多，但不接自己的历史表现，建议像通用文案生成。
- **工具碎片化**：爬虫风控重、扩展易失效、Skill 各装一套——创作者真正需要的是「装一次、在常用 AI 里直接问」。

现状代价：发得越多越盲目；60 篇量级本该够做统计分析，却因链路断裂而浪费。

## The Solution

作者在常用 AI Agent 中安装本仓库 Skills，并用配套导出能力拿到自己的后台数据，然后：

1. **一键导出（扩展）**：登录自己的公众号后台 → 扩展抓取已发表数据 → 结构化 CSV/JSON（也可降级为粘贴导入）  
2. **复盘诊断（吃自有数据）**：在自己的 60 篇里比高低——哪篇相对更好、标题/发布时间有何差异；**不要求绝对阅读量高**  
3. **爆款拆解（吃赛道样本）**：用内置/社区 `references` 或用户粘贴的同赛道公开爆款（标题+正文结构），学模式；**不依赖作者自己爆过**  
4. **修改建议**：多候选标题 + 开头/结构方向 + 1–3 个可验证实验  
5. **落地页**：GitHub README = 价值主张 + 扩展+Skill 安装矩阵 + 示例 IO  

运行时大模型由用户本地 Agent 提供——开源交付的是**流程、语料、诊断框架、导出扩展与提示词**，不是托管 SaaS。

## What Makes This Different

| 相对 | 差异 |
|------|------|
| 纯标题 Skill（lengyi / bigpeng 等） | 接**自有数据证据**，不是只吐标题 |
| 纯抓数插件（wechat-mp-data-scraper） | 不止导出，还给诊断与下一篇实验 |
| 爬虫/对标工具 | 默认合法自有数据；对标为增强，非核心 |
| 运营 SOP 套件 | 产品叙事锁在「质量闭环」，安装路径对齐五端 Agent |

不诚实的「护城河」不写。真正优势是：**闭环定义清晰 + 跨 Agent 一键装 + 短篇/小说作者可先跑通再泛化赛道模板**。

## Who This Serves

**Primary：** 需要系统提升内容质量的公众号作者（个人/小团队），已在使用 Cursor / Claude Code / Codex / WorkBuddy / OpenClaw 之一，愿意粘贴或导出自己的后台数据。

**Dogfood：** 短篇小说公众号作者（60+ 篇）——验证「叙事类内容」的复盘维度（完读代理指标、开头钩子、悬念结构、标题信息密度）。

**Secondary：** 想学爆款结构的运营学习者；贡献赛道模板的开源贡献者。

## Success Criteria

**用户成功（MVP）：**

- 任一支持端 ≤3 分钟完成安装，用一份粘贴/导入数据跑出：复盘结论 + Top 因子 + ≥3 标题候选 + 1 份下一篇实验清单  
- 作者本人对 60+ 篇完成一次完整复盘，并据此改写 ≥1 篇后对比指标（人工记录即可）  

**项目成功（开源）：**

- README 安装矩阵覆盖五端；skills.sh / SkillHub /（可选）ClawHub 可发现  
- 外部作者无需改代码即可复现「导入 → 报告」路径  
- [ASSUMPTION] 90 天内获得有意义的 star/issue 反馈（具体数字待定）  

## Scope

### In（MVP）

- **导出扩展**：从用户已登录的公众号后台导出自己的已发表数据 → CSV/JSON  
- 标准 Agent Skills：复盘 / 爆款拆解 / 标题与内容建议  
- 输入契约：扩展产物优先；粘贴导入为降级路径；可选草稿正文  
- **爆款样本 = A+B（MVP）**：A 轻量内置短篇赛道蒸馏 references（标题/结构规律，非全文转载）；B 用户粘贴对标链接/正文  
- **C 自动对标后置**：可选接 wxrank/订阅池类能力，不作冷启动阻塞  
- 自有历史（扩展导出）只做相对复盘，不要求作者已爆 
- GitHub 中文落地 README + 演示 + 扩展/Skill 安装说明  
- 分发：`npx skills add`、SkillHub、OpenClaw/ClawHub  

### Out（V1 明确不做）

- 承诺推荐位/保证爆款  
- 自动登录公众号、代持账号  
- 大规模爬取他人账号作为默认路径  
- 托管 SaaS 与账号体系  

### Later（有意后置）

- 轻量 Web：上传 CSV → 出报告  
- 第三方热度 API（付费闸门清晰）  
- 赛道模板市场（社区贡献） 

## Distribution Insight（调研摘要）

跨工具已收敛 **Agent Skills** 标准。便利性排序见 addendum；MVP 原则：**同一套 `skills/`，README 只留三条复制即装命令**，比自建五套插件更划算。

## Vision

成为公众号创作者默认的「质量复盘副驾驶」：Skill 是入口，赛道模板可插拔，数据接入可增强但不绑架；社区贡献各垂直（小说、职场、AI…）的 references，形成开源运营知识库——而不是又一个短命爬虫。
