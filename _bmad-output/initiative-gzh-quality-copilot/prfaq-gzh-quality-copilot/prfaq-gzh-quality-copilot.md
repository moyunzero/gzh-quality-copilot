# 开源发布：GZH Quality Copilot —— 用你自己的历史数据，决定下一篇怎么改

## 给几乎没人看、又不愿瞎猜算法的公众号作者：把「发完靠运气」换成「每篇有证据的实验」。

**GitHub / 开源社区，2026 年 10 月 20 日** — 今日开源项目 **GZH Quality Copilot（公众号质量 Copilot）** 正式公开。它面向认真做微信公众号、却长期拿不到自然流量的作者：在你常用的 AI 工具里装上一套 Skills，导出或粘贴自己的后台数据，就能对自己的历史文章做相对复盘、拆解赛道里真正打爆的结构，并拿到下一篇可验证的标题与内容实验——**不承诺推荐位，不保证爆款，只把「值得被看见」的质量决策做扎实。**

发得出去，不等于有人看。后台里躺着阅读、点赞、在看，作者却仍凭感觉改标题、凭感觉换开头；市面上有的只导出表格，有的只吐标题公式，有的一句话写完全文进草稿箱——中间缺的是：用**自己的证据**说清楚「哪篇相对更好、为什么、下一篇试什么」。没有这条闭环，文章质量再用力，也很难变成可积累的改进，更谈不上稳定变现。

GZH Quality Copilot 改变的是作者每周的工作方式：你不再从空白页猜「什么能火」，而是先看自己过去几十篇里谁赢谁输，再对照同赛道爆款的标题与结构规律，最后带着 1–3 个写得清、量得着的实验去写下一篇。推荐与否仍由平台决定；你掌控的是——少浪费一篇、多留下一次对照。

> 「我们不想再卖『流量密码』。作者真正缺的，是对自己历史诚实、对下一篇可验证的副驾驶——开源，是为了让这套方法能被检查、被改、被各赛道贡献者接下去。」
> — 项目维护者，GZH Quality Copilot

### How It Works

1. 在 Cursor / Claude Code / Codex / WorkBuddy / OpenClaw 等已在用的 Agent 里，用一条安装命令装上本仓库 Skills。  
2. 用配套浏览器扩展（或粘贴导入）导出**自己**公众号后台已发表文章的数据。  
3. 对着历史数据问：「我哪几篇相对更好？标题和开头差在哪？」——得到复盘结论与 Top 因子。  
4. 需要时粘贴同赛道公开对标（或使用仓库 `references/` 中可核对的短篇结构规律摘要，无全文），拆结构。  
5. 拿到 ≥3 个标题候选、开头/结构方向，以及 1–3 个下一篇实验；发完后再把新数据喂回来对照。

> 「以前改标题全靠感觉。现在至少知道：在我这 60 篇里，哪类开头相对不那么惨，下一篇该试哪两个变量——推荐还是玄学，但我不再两眼一抹黑。」
> — 短篇小说公众号作者（dogfood 场景）

### How to Participate

- 仓库：`gzh-quality-copilot`（GitHub；中文 README 即落地页）  
- 安装：复制 README 里面向你所用 Agent 的一条命令（`npx skills add` / SkillHub / OpenClaw 等）  
- 第一次成功：导入一份自己的数据（或示例 CSV）→ 跑出复盘 + 标题候选 + 实验清单  
- **预期对齐（避免新人/老人错位）：** **有历史篇数 → 复盘你自己；篇数很少 → 先当结构教练 + 实验本，不装懂你的数据。** 阅读量高低不是门槛；篇数决定复盘深浅（详见 Customer FAQ Q4）。维护者 dogfood「60+ 篇」只是案例量级，不是入场条件。  
- 贡献：提交赛道 `references`、改进诊断维度、反馈扩展在后台改版后的适配

## Customer FAQ（定稿）

> 交叉评审：xAI Grok · Moonshot Kimi · Cursor Composer（三家置信度均为 4/5）。下列为共识合成稿。

### Q1: 你不保证推荐，那对我「没人看 → 挣不到钱」到底有什么用？

A: 推荐开关在平台手里，我们不打开，也打不开。你每次能拿走的是三样**中间收益**：① 只跟你自己比的复盘——哪几篇相对没那么差，差在标题、开头还是结构（阅读量低也能做，见 Q4）；② 下一篇改法——≥3 个标题候选、一个开头/结构方向、1–3 个一次只动一个变量的实验，发完用新数据对；③ 结构参照——`references/` 里可核对的规律摘要，或你自己粘贴的对标拆解。

这些不直接变成钱。它们让你少盲发、多留下对照；真有人看见时，你知道哪种写法值得再写。若你要的是「装上就涨粉 / 就有稿费」，我们帮不了这个承诺——请换别的预期，而不是硬装这个工具。

### Q2: 这和市面上的标题生成类 Skill 有什么区别？

A: 标题类工具强项是「给你一批标题」。我们强项是：**先吃你自己导出的表现数据做相对复盘**，再出标题与实验；每个候选尽量带「下一篇怎么验」。结构参照只有两条合法路径：仓库 `references/` 中人工标注的公开样本结构规律摘要（无全文、出处可查），以及你自己粘贴的公开对标。只要标题、不要复盘，用标题类 Skill 更轻；要「为什么改、改完怎么验」，才是我们。

### Q3: 我已经在用「一句话成文、进草稿箱」的写作流水线了，还需要这个吗？

A: 那类工具主路径是**生产与发布**；我们主路径是**质量复盘与下一篇实验**。可以并存：用它们写，用我们在发前/发后做证据复盘。多花几分钟装一套 Skill，换的是固定尺子，不是第二套代写。我们默认不代持登录、不进草稿箱——那是另一类产品的合规与维护取舍，我们有意不碰。

### Q4: 我历史阅读几乎全是个位数，相对复盘有什么统计意义？不就是安慰剂？

A: 先澄清：**相对复盘需要的是历史篇数，不是阅读量。** 个位数阅读的作者正是目标用户；低阅读只说明不能讲「标题导致涨粉」的因果，不说明你的数据没用。

篇数决定我们把话说到多硬（产品口径，不是统计学定律）：

| 历史篇数 | 工具怎么做 |
|---------|-----------|
| **≥30 篇** | 相对排序 + Top 因子；若阅读仍是个位数，结论标**低置信**，只用来选下一篇实验，不假装显著因果。 |
| **10–29 篇** | 不做细分位。粗分「稍好 / 普通 / 较差」+ 结构对照 + 1–2 个小实验。 |
| **&lt;10 篇** | 不做排序、不编「你的数据证明了什么」。用结构规律摘要 + 你粘贴的对标，定 1 个结构实验；你的号先当基线攒着。 |
| **几乎没稿** | 建议先积累再来复盘排序；工具可先当检查清单用，但不假装有个人史证据。 |

维护者 dogfood 里「60+ 篇对照比较像样」是案例量级，**不是入场门槛**。篇数少就降级继续用，不必等阅读好看才开始。

### Q5: 数据会不会被你们拿走？扩展要登录公众号，安不安全？

A: 分三层：

1. **扩展**：只在你已登录的后台读取**本号已发表**数据，导出到本地 CSV/JSON。不代持登录、不代发、不读别人的号、不上传到本项目服务器（我们没有托管账号体系）。README 有一张给非技术读者的**权限清单**——对照清单即可，**不必读代码**；会写代码的人可用清单核对源码，不一致就是缺陷。  
2. **Skills**：提示词与 `references/` 开源，跑在你自己的 Agent 里。  
3. **模型 API（唯一会离开本机的环节）**：你贴进对话的表格与正文，会发给**你选用的**模型服务商；密钥、账单与隐私条款是你与该服务商之间的事，我们看不到这场对话。「导出在本地」≠「贴进对话后仍不出电脑」。敏感内容请脱敏；介意云端可换本地模型（质量取决于模型能力）。

### Q6: 微信改版后扩展挂了怎么办？项目黄了呢？以后会收费吗？

A:

- **扩展挂了（非技术）**：永远可降级为粘贴/手工导入；复盘与实验照跑，只是少了自动导出。  
- **扩展挂了（技术）**：适配开源，可自修或等社区；我们不承诺每次跟上微信 DOM，也无商业 SLA。  
- **项目停更**：已装在你机器上的 Skill 与本地 CSV 仍在，没有云端账号会被关掉；之后只能靠粘贴。会写代码的人可以 fork。  
- **定价**：MVP **免费开源**；是否做付费层**未定**——若有，会明示；开源 Skills 本体保持可自用。

### Q7: 装起来要多久？我不会写代码。新人几乎没稿，装了有用吗？

A: 前提：你已经在用支持的 Agent 之一（Cursor / Claude Code / Codex / WorkBuddy / OpenClaw）。你需要会三件事：① 打开 README 看权限清单；② 复制对应的一条安装命令；③ 把示例 CSV 或自己的数据粘贴进对话。**目标**（尚未逐端实测，以 README 为准）：装上并用示例跑出第一份报告约数分钟量级。不需要搭爬虫、不需要写代码。

装上之后预期要对齐：**有历史篇数 → 复盘你自己；篇数很少 → 先当结构教练 + 实验本，不装懂你的数据。** 纯新人也能用，但不会假装从「几乎空白的个人史」里挖出规律；老人（篇数多、哪怕阅读个位数）才能跑完整体相对复盘。分层见 Q4。号开很久但只发过几篇，按篇数降级，不按「是不是老人」升级。

你若完全不用这类 Agent：MVP **覆盖不到**；轻量 Web 上传属 Later，当前不承诺上线时间。

### Q8: 能帮我扒竞品号的真实阅读量吗？内置规律是不是也是扒的？

A: **默认不做扒竞品、不抓别人真实阅读、不把他人全文收进仓库。**

内置材料只有短篇赛道的**结构规律摘要**：维护者阅读公开文章后的**人工标注**，放在 `references/`，每条可查「依据哪类公开样本、摘了什么结构信号」，**无正文全文**。你要拆某一篇，自己粘贴已公开的正文或链接。

自动全网对标、付费拉他人真阅读，是后置可选项且有合规边界，MVP 不碰。若你的核心需求是系统监测别人的号，请用商业监测类工具——那不是我们的主菜。

### Q9: 短篇小说以外的赛道现在能用吗？

A: 复盘与实验框架通用。内置结构规律摘要首发偏短篇 dogfood；其他赛道靠你粘贴同赛道公开对标即可用，质量取决于样本。工具只做结构拆解与对照，**值不值得学由你判断**。社区按同一格式贡献其他赛道摘要（规律 + 可查出处 + 无全文）是后期；现在不假装「全赛道专家库已装满」。

### Q11: 我直接问 ChatGPT（或别的通用助手）「帮我分析这几篇」不就行了？

A: 单次闲聊，直接问往往够用。差别在你要**第十次还用同一把尺子**时：① 固定诊断维度与输出结构（结论 / 因子 / 候选 / 实验）；② 篇数不足时按 Q4 **强制降级**，而不是照样画分位装懂；③ 结构判断落到可打开的 `references/` 或你贴的原文；④ 每条判断尽量带依据片段（见 Q10）。模型来自你选用的那一家——Skill 不会比它更懂微信算法；固定的是流程，不是神谕。一年只复盘一次，通用助手够；要每周对照积累，装 Skills 更省事。

### Q10:【怕被问的那句】说白了，这就是让大模型读我的表然后胡说一通——我为什么要信？

A: 该信的不是「模型有灵」，而是**你能按片段反驳的句子**。产品须兑现：报告里每条重要判断带依据片段（你表里的哪几行、正文哪一段、或 `references/` 哪一条）；给不出片段的标为「推测」。输出固定四块：结论 / 因子 / 候选 / 实验；实验要等你发完用新数据对照。提示词与诊断维度开源。解释不通就丢掉，别当圣旨——工具逼你留下对照，不替你迷信一次生成。

## Internal FAQ（定稿 · 开源 / 个人维护者口径）

### I1: 最难做、最容易翻车的技术点是什么？

A: 两块，不是「接大模型」：

1. **浏览器扩展跟微信后台 DOM**：改版即挂；这是已知脆点，必须以粘贴导入为永久一等公民路径，扩展是便利层不是唯一路径。  
2. **把 Customer FAQ 写成的产品债做实**：篇数强制降级、报告「无依据→标推测」、`references/` 可查出处、README 权限清单。这些比多写一个标题模板难——难在约束模型胡说，而不是生成文案。

未知：各 Agent 安装路径与触发词是否真能「数分钟首跑」——上架前要用五端各跑一次冒烟，跑不通就改 README 目标，不改话术硬撑。

### I2: MVP 最小可发布范围是什么？明确说不做什么？

A: **必须有：** 输入契约（CSV/粘贴）+ 复盘 Skill（含篇数降级）+ 结构对照（references 摘要 + 用户粘贴）+ 标题/实验输出（固定四块 + 依据片段）+ 中文 README（安装矩阵、权限清单、预期对齐）+ 示例数据。扩展：能用就带；发版前挂了也不挡发布（粘贴路径绿）。

**明确不做（说不）：** 保证推荐、代持登录进草稿箱、默认扒竞品真阅读、托管 SaaS/账号体系、全赛道专家库装满、商业 SLA。

### I3: 现实时间线？一个人怎么排？

A: 建议三刀（可按你日历改数字，不可改顺序）：

| 切片 | 产出 | 验收 |
|------|------|------|
| **Dogfood 竖切** | Skills + 示例 CSV + 用维护者真实历史跑通一遍 | 自己能留下「结论→实验→发后对照」一次 |
| **开源可安装** | README 五端命令 + 权限清单 + references 来源页 | 陌生人按文档用示例跑出报告（可请一人代测） |
| **扩展（可并行可后置）** | 本号已发表导出 | 在当前后台版本导出成功；失败则文档降级到粘贴 |

未经验证的乐观值不写进对外材料。对内：若两周内 dogfood 竖切都跑不通，先停扩展，先修流程。

### I4: 维护负担谁扛？项目会不会变成「又一具扩展尸体」？

A: 扩展必然周期性失效——接受。对抗方式：核心价值在 **Skills + 粘贴**，扩展标为「尽力维护」；Issue 模板区分「扩展挂了」vs「诊断胡说」。可持续性靠：输入契约稳定、示例数据常绿、欢迎社区 PR 修 DOM，而不是维护者承诺 7×24 跟微信。

贡献者参与点：赛道 `references`、诊断维度、扩展适配——比「再写一个写全文 Skill」更对齐定位。

### I5: 前 100 个使用者怎么来？（开源采纳，不是获客漏斗幻觉）

A: 路径现实且窄：GitHub README（中文落地）→ skills.sh / SkillHub / ClawHub 发现 → 短篇/公众号作者社群里贴「导入→报告」演示（脱敏）。不靠投放。成功信号：外部作者**不改代码**复现路径 + 有意义的 star/issue（Brief 里 90 天数字仍是 ASSUMPTION，Verdict 前可再定或保持模糊）。

风险：诚实叙事「不保证推荐」转化弱——用演示证明「中间收益」可见，而不是硬广涨粉。

### I6: 护城河是什么？开源了还剩什么？

A: 不写虚假护城河。能积累的是：**闭环定义清晰 + 可检查的诊断框架 + dogfood 沉淀的短篇 references + 跨 Agent 一键装。** 竞品可抄提示词；抄不走的是你持续对照后留下的赛道摘要与「依据片段」约束习惯。若这些不做实，开源只是又一个 ChatGPT 包装——见 I10。

### I7: 什么会直接杀死这个项目？

A:

1. **合规雷**：扩展越权、或宣传像破解推流 → 信任与账号风险。  
2. **FAQ 空头支票**：写了降级/依据片段/权限清单，仓库里没有 → 第一批用户当营销撕。  
3. **references 空洞或含全文**：版权与「不扒竞品」口径自爆。  
4. **Dogfood 零对照**：维护者自己都不做「实验→再量」，社区不会信。  
5. **只卷扩展、不卷粘贴**：微信一改版，仓库变坟场。

### I8: 法律 / 平台暴露？

A: 扩展仅本号已登录后台已发表数据；不对他人号批量抓取。内置 references 无全文、出处可查。用户把正文贴进第三方模型 API——责任在用户与其服务商（Q5 已对外说明）。仓库 LICENSE（建议 MIT，Brief 仍 ASSUMPTION）与「禁止用于破解推荐/未授权采集」声明写进 README。不做「保证上推荐」广告法风险话术。

### I9: 为什么是现在？为什么是我们（维护者）做？

A: **现在：** Agent Skills 分发已收敛；开源采集链路因接口/改版变脆 → 「自有数据 + 本地 Agent」窗口大；推荐权重上升使盲发代价更高。  
**我们：** 有真实短篇号可 dogfood，愿意公开「不保证推荐」；目标不是做成又一个写手流水线。若维护者不肯用自己的号每周对照，就没有「为什么是我们」。

### I10:【维护者半夜会想、却常不说出口的】——若 dogfood 做完，相对阅读也没好，这项目还该开源吗？还是其实只是套了壳的 ChatGPT？

A: 必须先答「和直接问通用助手的差别是否可演示」：同一份 CSV，Skills 是否稳定给出降级/依据片段/实验清单，而闲聊是否每次漂移。若演示不出流程差，**先别开源海报，先修 Skill**。

相对指标没改善，不等于产品失败——样本噪声大、平台侧主导；失败标准应是：**作者无法解释实验、或工具编造无依据结论**。若 dogfood 证明工具只会安慰剂报告，诚实选择是：收窄为「结构检查清单」开源，或停更，而不是改口承诺涨粉。

## The Verdict

### Concept Strength

**叙事与边界已锻成；执行证明仍需加热。**  
经过 Ignition → 新闻稿（锁定诚实框架 A）→ Customer FAQ（三商家交叉定稿）→ Internal FAQ，概念不再靠「更多推荐」撒谎，缝隙（自有证据闭环）说得清，新人/老人预期也对齐了。这足以进入规划（Spec / 轻量 PRD），**还不足以开香槟上架**：FAQ 里每一条产品债若仓库里没有对应物，概念会在第一批用户手里碎掉。

### Forged in steel（已锻成）

- **诚实结果叙事（框架 A）**：中间收益 = 相对复盘 + 可验证实验；不承诺推荐位/爆款。  
- **竞品缝隙**：标题 Skill / 写作流水线 / 监测扒数各占一截；「自有数据 → 诊断 → 实验 → 再量」仍薄。  
- **篇数 ≠ 阅读量** + 分层降级表；60+ 仅 dogfood 案例。  
- **内置规律口径**：人工标注公开样本、`references/` 可查、无全文；与「不扒竞品」一致。  
- **粘贴一等公民、扩展尽力维护**：防开源扩展坟场。  
- **I10 失败标准正确**：看「能否解释实验 / 有无依据胡说」，不看单次阅读是否上涨。

### Needs more heat（还需加热）

- **Dogfood 竖切尚未发生**：维护者真实历史「结论→实验→发后对照」一次都还没有。  
- **五端安装冒烟**未做；「数分钟首跑」仍是目标。  
- **LICENSE、中文正式品牌名、90 天成功数字**仍是 ASSUMPTION。  
- **扩展是否与 MVP 同船首发**未钉死（Internal 允许后置——规划里写清即可）。  
- **短篇 `references/` 实质内容**还是空壳承诺。

### Cracks in the foundation（地基裂缝 · 须刻意处理）

1. **空头 FAQ**：降级 / 依据片段 / 权限清单 / 来源页写进对外材料后必须落地——否则比「保证推荐」更伤（自我打脸）。**补救：** Spec 把这四条列为 launch blocker，不是 polish。  
2. **ChatGPT 套壳风险**：若演示不出与闲聊的流程差，开源海报会暴露空洞。**补救：** 发版前固定「同 CSV：Skill vs 裸聊」对照演示。  
3. **合规越权诱惑**：扩展或宣传一旦滑向扒竞品/破解推流，杀死信任。**补救：** README 禁令 + 代码权限与清单一致。

### 总判

| 问题 | 判断 |
|------|------|
| 该不该做？ | **该**——痛点真实，定位与市面缝隙对齐，诚实框架可守。 |
| 概念过关了吗？ | **过关（可规划）**——不是「立刻全球发布」。 |
